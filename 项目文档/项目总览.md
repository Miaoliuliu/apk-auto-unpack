## 1. 项目定位

**auto-unpack v0.1.0** —— APK 壳识别、脱壳（unpacking）与 URL 提取的自动化流水线。

面向灰产对抗场景的批量样本处理工具：

1. 识别 APK 是否加壳、什么壳（14 家厂商特征库 + dex 结构 + APKiD 补强）
2. 对可自动脱壳的（dpt-shell）做 frida 动态 dump；其余走静态提取或转人工
3. 从 DEX 字符串池 / assets / resources.arsc / native .so / manifest 中提取 URL，三档分级输出

## 4. 端到端数据流

```
CLI（auto-unpack analyze|detect）
  └─ flow/cli.py → pipeline.run()
       ├─ [1] ingest          sample.validate_apk（PK头/炸弹防护）→ 三哈希 → read_apk_meta
       ├─ [2] detect          packer_sigs.detect（特征库+dex结构）→ route
       │     └─ APKiD 合并    apkid.run_apkid → merge_apkid（只补强不覆盖）
       ├─ [3] 归档            outputs/packer_detection/<壳名>/apk 拷贝 + 去重清理
       ├─ [4] 分流            suggest_route → adapter 选择
       │     ├─ dpt-shell     → 动态脱壳（frida spawn + dump.js）
       │     │     └─ validate（is_payload_dex / shell_ratio / 补扫原包）
       │     ├─ static        → 静态提取（无壳/360 等）
       │     ├─ manual        → VMP·付费壳，转人工
       │     ├─ unknown       → 自研保护（JDog/packhub/根dex stub/读不出dex）→ 不抽 URL 转人工
       │     └─ skip          → 跳过
       ├─ [5] 提取            analyze.extract_indicators（dex字符串→assets→arsc→so→manifest→二进制）
       │     └─ indicators.url_rank 三档分级
       └─ [6] 产物            outputs/unpacked_dex/<apk名>/（仅动态） + outputs/extracted_urls/<apk名>/urls_by_rank.txt
```

状态机：`RECEIVED → VALIDATED → DETECTING → (NO_PACKER|PACKER_*) → UNPACKING → UNPACKED → EXTRACTING → COMPLETED | NEEDS_REVIEW | FAILED`

## 5. packer要点

- **PACKERS 特征库**：14 家（360/乐固/爱加密/梆梆/娜迦/阿里/百度/网易易盾/顶象/通付盾/几维/LIA/V++/OPPO），so/assets/stub 三类特征
- **VMP 判定**：白名单 `libchaosvmp/libsgavmp/libdxvmp/libdexvmp/libvmpc/libVMDexShellx`；注意 libjiagu*.so 不当 VMP
- **dpt-shell 四级判定**：standard（特征文件）/ modified（native 符号）/ appended（classes.dex 尾部 ZIP）/ suspected
- **自研保护**：JDog native loader（com/jdog/JLibrary + `__LoadDexLow` 等符号）、packhub_shell、随机 lib + hex 8 位成对（lib39285EFA.so + assets/39285EFA.dex）、根 dex stub、读不出 dex → 统一 route=unknown，对外名"自研保护"，**不抽 URL 转人工**
- **APKiD 只补强不覆盖**：vmp 合并、has_shell、suspicious；anti_hook 只作参考不判壳
- 畸形 manifest（androguard 崩）本身是壳特征

## 6. 动态脱壳（仅 dpt-shell 实现）

- frida spawn 注入 `dpt_shell_dump.js`，`_on_message` 收 dex 写盘
- **参数下标**：DefineClass=5（Handle 两槽则 6）、LoadMethod=2/1（依 Itanium 符号名）
- **硬校验** `is_valid_dumped_dex`：magic + header_size==0x70 + file_size==len，无效隔离 `_invalid_dex/`
- **等待逻辑**：至少 12s，连续 5s 无新 dex 提前结束
- 产物校验和损坏 → `fix_dex_header` 重算 adler32/sha1

## 7. URL 提取要点

- 提取顺序：DEX 字符串池 → assets 文本 → resources.arsc → native .so（≤32MB/48 个）→ manifest → 二进制浅扫（URL/IP 字节正则）；无相关 URL 时 deep 回扫
- **三档分级**：biz（灰产 TLD/php·api 路径/ws/IP 带路径）> weak > noise；`urls_by_rank.txt` 只写 biz→weak；噪音表含 SDK/框架/证书链/公共 DNS IP
- **配置收割** `_harvest_config`：baseUrl/domainList/apiUrl 等键 + host×接口路径还原
- **关键约定：没 dump 不写 URL**（自研保护转人工时 write_urls=False）

## 8. 产物布局与归档约定

| 目录 | 内容 | 备注 |
|---|---|---|
| `APK/` | 待分析 APK | 主进程无路径时扫描这一层；也可用 `--inbox` 指向别处 |
| `outputs/packer_detection/<壳名>/` | 归档 APK | 标签变了清其它目录同名同大小旧拷贝 |
| `outputs/unpacked_dex/<apk名>/` | dump 的 dex | 仅动态脱壳成功才写 |
| `outputs/extracted_urls/<apk名>/` | urls_by_rank.txt + meta | 只写 biz→weak |

- 目录名映射：dpt-shell→`dpt-shell`（变体统一）、packhub/JDog/unknown→`自研保护`
- 可读文件名 > 可信包名 > `apk_<hash>`

## 9. CLI 与退出码

- `auto-unpack`（analyze flow，无路径读 `APK/`）/ `auto-unpack-router`（apkid）/ `auto-unpack-detect`（packer_sigs）/ `auto-unpack-analyze`（analyze）
- 退出码：0 成功 / 1 无 URL / 2 输入非法 / 3 识别失败 / 4 脱壳失败 / 5 其他失败

## 10. 关键约定与坑（务必遵守）

1. **不设 `PYTHONUTF8=1`**；Windows 上 stdout 靠 `sys.stdout.reconfigure(encoding="utf-8")`（`__init__.py` 已全局处理）
2. **批量 detect 必须 `logger.remove()`**（`__init__.py` 已做；但单独调 packer_sigs 时注意）
3. **畸形 Manifest 包名不能乱猜**——`Kcom.google...` 这类字符串池启发式结果不可信，不能用于 frida spawn（`pkg_name.resolve_spawn_package_info` 只信 CLI --package / adb 安装 / 可信静态解析）
4. **假 dex 诱饵防护**：非 ASCII 路径跳过 + `dex_header_plausible` O(1) 头校验（size×entry 落文件内、off≥0x70），诱饵声明几十亿 TYPE_ID 当场拒收
5. **假 ZIP 加密标志**按普通 dex 解析（清标志 inflate），不能当加密跳过
6. **DomapiApiFlag monkey patch** 必须在 `dex_utils.py` 模块顶层（Android 13+ apiFlag=4/6 枚举缺失），否则裸 dex 解析崩
7. **没 dump 不写 URL**；归档时清理其它目录同名同大小旧拷贝
8. **未实现**：360 dump、JDog 动态、厂商壳（14 个 UNPACK_FLOWS 均未实现）；VMP·付费壳转 manual
9. 包名获取优先级：CLI --package → adb install diff → APK 静态解析（不可信则报 E_BAD_PACKAGE）
10. **动态脱壳默认关闭**：env.json `unpack=false` 时不执行 APK（防误装）；install 三模式 never/when_needed/always
